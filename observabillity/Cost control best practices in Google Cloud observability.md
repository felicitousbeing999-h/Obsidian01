## Logging costs

There are 3 main best practices to control logging costs: Exclude logs, export logs, and reduce Ops Agent usage.


### Exclude logs
Exclude certain logs based on high volume or the lack of practical value. Most common exclusions: Load balancers, VPC Flow Logs (still incurs costs) and Web applications.

### Export logs
Export logs yet exclude them from being ingested into Cloud Logging. Export logs to: Cloud Storage, BigQuery, and Pub/Sub

### Reduce Ops Agent usage

Choose not to add agents in nonessential environments. Reduce log volumes by not sending the additional logs generated by the Ops Agent to Cloud Logging.

> [!NOTE]
**If you exclude log entries, you don't pay for them. However, they will be gone once excluded, so be careful with the log entries you keep.**

## Prometheus costs

There are 3 main best practices to control Prometheus costs: Reduce the number of time series, reduce the number of samples collection, and configure local aggregation (self-managed collection only).
_utton to expand the best practices to learn more._

##### Reduce the number of time series

- Increase the length of the sampling period.  
    _For example__, changing a 10-second sampling period to 30 seconds can reduce your sample volume by 66%._
    
- Set the scraping interval on a per-job or a per-target basis.
    

##### Reduce the number of samples collection

- Do not send detailed system metrics from third-party apps.
    
- Set the scraping interval on a per-job or a per-target basis.
    

##### Configure local aggregation (self-managed collection only)

Aggregate high-cardinality metrics locally by using recording rules, flags, and environment variables.

## Trace costs

[Trace(opens in a new tab)](https://docs.cloud.google.com/trace/docs) charges are based on the number of trace spans ingested and scanned. There are 3 main best practices to control Trace costs: Use OpenTelemetry sampling, use Cloud Trace API span quotas, and optimize third party callers.

#### OpenTelemetry sampling

Use the sampling feature to reduce the volume of trace ingestion.

- Reduce sampling to one-fourth.  
    _For example, with a popular web application with 5000 queries/second, you might gain enough insight from sampling 5% of your app traffic instead of 20%._
    
- Use OpenTelemetry to specify sampling.

### Cloud Trace API span quotas
Enforce span quotas to ensure that your project does not cross quota limit
### Third party callers
Understand how instrumented apps interact to assess the effect of the number of spans ingested.

If your app reports spans, the number of spans reported by your app might depend on the incoming traffic that you receive from the third-party app.

_For example, if you have a frontend microservice that calls a checkout microservice, and both are instrumented with OpenTelemetry, the sampling rate for the traffic is at least as high as the frontend sampling rate. Understanding how instrumented apps interact lets you assess the effect of the number of spans ingested._
